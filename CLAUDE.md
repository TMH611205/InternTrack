# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

InternTrack is a Vietnamese-language internship and graduation-thesis management app for Vinh University (roles: student, company, lecturer, admin). Plain PHP 8.2 + PDO/MySQL on Apache/XAMPP, no framework, no build step, no test suite or linter. `README.md` (Vietnamese) has full setup, OTP/Gmail and production notes.

## Commands

- Install deps (PHPMailer, dompdf for PDF export): `composer install`
- Run: start Apache + MySQL in XAMPP, open `http://localhost/InternTrack/`
- DB setup: create DB `interntrack` (utf8mb4_unicode_ci), import `database/interntrack.sql` (idempotent `CREATE TABLE IF NOT EXISTS`), then optionally `database/seed.sql` (local demo accounts only).
- Upgrade an existing DB: `C:\xampp\php\php.exe scripts\migrate.php` (adds missing tables / columns / ENUM values from `interntrack.sql`; idempotent; `--database=<name>` targets a copy). When you change the schema, edit `database/interntrack.sql` only; the migrator derives ALTERs from it.
- Scheduled jobs: `scripts/cron.php` (hourly) runs daily reminders and a daily backup into `backups/` (git-ignored, web-blocked).
- Syntax check a file: `C:\xampp\php\php.exe -l <file>`
- Config comes from env vars or a single git-ignored `.env` (there is no `.env.example`; the variable list is in `README.md`): `DB_*`, `MAIL_*`, `GEMINI_API_KEY`/`GEMINI_MODEL`. Never commit `.env` or put secrets anywhere tracked. Read via `app_env()` in `config/app.php`.

## Architecture

Single front controller: everything goes through `index.php`.

- **Routing**: `?page=<role>/<screen>` must be in the whitelist `$availablePages` in `index.php`; adding a screen means adding it there, plus a view under `views/<role>/`, plus an entry in `views/layouts/page-data.php`. The role prefix must match the user's role (else 403); `auth/*` are the only public pages.
- **POST flow**: `index.php` checks CSRF (`app_valid_csrf`), handles auth/OTP actions inline, and delegates all other `action` values to `handle_workspace_action()` in `controllers/ActionController.php`, which does role checks (`action_user`), validation (`action_value`), DB writes, and returns a redirect page. User-facing errors are thrown as `DomainException` (shown as a flash); any other `Throwable` is logged and replaced by a generic message. Post/redirect/get with `app_set_flash`/`app_take_flash`.
- **GET flow**: `?download=<type>&id=<n>` is served by `serve_workspace_download()` (permission-checked); otherwise the view is `require`d. Files in `uploads/` are blocked by `.htaccess` and must only be served through that endpoint.
- **Views are data-driven**: each role view calls the shared `views/layouts/screen.php`, which loads a per-screen config from `views/layouts/page-data.php`, hydrates it with live DB data via `load_screen_data()` in `controllers/PageController.php` (queries via `page_all`/`page_one`/`page_count`), and renders through `header.php`/`content.php`/`footer.php`. Look at `page-data.php` + `PageController.php` + `content.php` together to change a screen.
- **Auth**: `controllers/AuthController.php` (session login, password-reset OTP stored as SHA-256 hash, 60s expiry, 5 attempts, 60s resend). Mail is sent via PHPMailer in `app_send_password_reset_otp()` (`config/app.php`).
- **Data access scoping**: internship access is scoped per role by `action_internship()` (student/company/lecturer id on `internships`); reuse it rather than writing ad-hoc ownership checks.
- **Closing an internship**: setting status `completed` (in `internship_update`) requires submitted evaluations from both company and lecturer; it then stores `final_score` (weights/pass mark in `FINAL_SCORE_WEIGHTS`/`FINAL_PASS_SCORE`, top of `PageController.php`). Completed/cancelled internships are locked against new tasks, reports, evaluations and student task updates via `action_require_open_internship()`.
- **Messaging**: 1-1 direct messages between student, company and lecturer (`messages` table, `controllers/MessageController.php`, pages `<role>/messages`, action `message_send`). `message_contacts()` is the single permission source: two users can talk only if they share a non-cancelled internship; admin does not take part. Opening a thread marks it read and clears its `notifications` row (link `<role>/messages&with=<userId>`); the page polls itself every 6s from `assets/js/app.js`. A message may carry one attachment (`store_uploaded_file(..., 'messages', 10 MB)`; `file_path`/`file_name` columns); it is served only to sender/recipient via `?download=message&id=<messageId>` (`&inline=1` renders raster images in the thread, never anything else). `app_redirect()` accepts a trailing `&query` in the page string for this.
- There is no `models/` layer; SQL lives in the controllers. Wrap multi-step writes in `database_transaction()` (`config/database.php`).
- **AI (Gemini)**: `controllers/AiMatchController.php` holds the API core (`ai_gemini_generate`, retries on 503), CV-to-position matching (`ai_matches`) and the student chat bubble (`ai_chat_reply`, served by the JSON branch `action=ai_chat` in `index.php`). `controllers/AiInsightController.php` holds diary/report summaries, risk warnings, final comments, skill stats and skill extraction; results are cached in `ai_insights` (kind + subject_id) and `skill_suggestions`. Feature buttons are hidden unless `ai_match_enabled()` (needs `GEMINI_API_KEY`). AI output must be re-validated server-side (ids, score range, verbatim evidence) and user text is passed to the model as data, not instructions. Rendering helpers are in `views/layouts/ai-insight.php`. After an AI action, set `$_SESSION['_open_dialog']` so the footer reopens the result dialog.
- Admin-managed knowledge for the chat lives in `kb_documents` (page `admin/documents`).
- **Thesis / batch module** (`controllers/ThesisController.php`): batches (`batches`, `batch_milestones`, `batch_students`), topics, preferences, groups, `theses`, milestones/meetings/versioned submissions + comments, rubric scoring (`rubrics`, `rubric_criteria`, `thesis_scores`), councils, regrades. Features open/close by milestone via `batch_phase_state()` / `batch_require_phase()`; a closed batch has `locked_at` and every write must call `batch_require_unlocked()`. Final thesis score = weighted average of supervisor / reviewer / council (`thesis_compute_final()`, weights on the batch). Access to one thesis goes through `thesis_access()`.
- **Internship batches**: when an internship batch is open, applying / self-placement needs the student on its list and inside its `registration` milestone (`internship_require_registration()`); internships carry `batch_id`, midterm/final reports and evaluations follow the batch milestones, and a closed batch locks them (`internship_require_batch()`, also called from `action_require_open_internship()`). No open internship batch = no restriction. Positions posted by a company go to `pending` until an admin approves (`approved_at`); content edits need re-approval. Batches may set `company_rubric_id` / `lecturer_rubric_id`; evaluations then score per criterion (`evaluation_items`) and `overall_score` = rubric total × 10. Companies confirm or flag diaries (`diaries.company_status`, page `company/diaries`).
- **Accounts / scope**: `authenticated_user()` returns `role` (active role from `$_SESSION['active_role']`), `roles` (users.role + `user_roles`), `scope_faculty` (admin limited to one faculty) and `is_mentor` (company mentor account from `company_mentors`). It also sets MySQL session variables `@it_faculty` and `@it_mentor`; admin list queries filter with `(@it_faculty IS NULL OR ... = @it_faculty)` and company internship queries with `(@it_mentor IS NULL OR i.mentor_user_id = @it_mentor)` — keep that clause when adding queries. `app_hidden_pages()` hides/blocks pages per account. SSO: `controllers/SsoController.php` (Google, existing accounts only).
- **Audit**: `AUDIT_TRACKED` maps actions to `[table, id field]`; `handle_workspace_action()` snapshots the row before and stores `{field: [old, new]}` in `audit_logs.changes`.
- **Exports**: `export_csv()` writes real `.xlsx` (pure-PHP `config/zip.php`, no zip extension needed; `&format=csv` for CSV); `export_print()` renders the school document layout as HTML, or a real PDF via dompdf with `&format=pdf` (logo JPEG, no GD needed). Signature rows / unit / place are configurable on `admin/templates` (`DOCUMENT_TEMPLATES`, `app_setting('doc_sign_*')`). Backups are `.zip` (database.sql + uploads/).
- **Internship extras** (`controllers/InternshipController.php`): allocation by preference (Gale-Shapley over positions, runs stored in `matching_runs` with `algorithm = internship_gs`), change / withdraw requests, weekly plans, daily warnings, report versions + comments (`item_comments`, `views/layouts/comments.php`). Content similarity of thesis submissions: `controllers/SimilarityController.php`. Training-system sync API: `controllers/SyncApiController.php` (`?api=sync`, `SYNC_API_KEY`).
- **Matching** (`controllers/MatchingController.php`): Gale-Shapley (both sides), Serial Dictatorship, Hungarian; locked / confirmed theses are kept and reduce capacity; runs are stored in `matching_runs` and only `matching_publish()` writes `theses`.
- **Admin tools** (`controllers/AdminToolsController.php`): audit log (`audit_record()`, called for every successful workspace action plus login/logout), daily reminders (`reminders_run_daily()` from `screen.php`, guarded by `app_settings`), announcements + calendar, statistics, CSV/print exports served by `?export=<type>` (`serve_export()`), SQL backup/restore, Excel/CSV user import, self-found placements, attendance, internship documents, company reviews, public company registration (`auth/register`).
- New screens use `kind => 'custom'` in `page-data.php`; their markup lives in `views/layouts/screens/<role>-<screen>.php` (shared helpers in `_common.php`, `_thesis-parts.php`). `load_screen_data()` falls through to `thesis_screen_data()` / `admin_tools_screen_data()`, and `handle_workspace_action()` falls through to `thesis_handle_action()` / `admin_tools_handle_action()` (each returns `['route', 'message']` or null).
- Demo data for the thesis module: `database/seed-thesis.sql`. `notify_user(..., $email = true)` also emails when `MAIL_NOTIFY=1`.
- `config/app.php` installs a global error handler that converts PHP warnings/notices into `ErrorException`, so sloppy code throws.
- Uploads: `store_uploaded_file()` validates real MIME and size (CV/report up to 5 MB, avatars 3 MB) into `uploads/<folder>/`.

## Conventions

- `declare(strict_types=1)` at the top of PHP files; UI strings and comments are in Vietnamese; escape output with `screen_escape()`.
- Always use PDO prepared statements via `database()` (`config/database.php`).
